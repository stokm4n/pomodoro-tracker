# Pomodoro Tracker

Веб-приложение для организации работы по технике Pomodoro. Пользователь может
планировать задачи, запускать рабочие интервалы и перерывы, отслеживать историю
и анализировать собственную продуктивность.

Проект разработан в рамках курсовой работы по дисциплине
«Технология разработки программных систем».

**Работающее приложение:** [pomotrack.ru](https://pomotrack.ru)

## Возможности

- регистрация и авторизация пользователей;
- Pomodoro-таймер с паузой, продолжением и досрочным завершением;
- автоматический выбор короткого или длинного перерыва после Pomodoro;
- настройка продолжительности работы и перерывов;
- создание, редактирование, выполнение и удаление задач;
- запуск рабочей сессии с задачей или без неё;
- история завершённых и отменённых сессий;
- статистика за день, неделю и всё время;
- календарь активности, статистика задач и графики времени фокуса;
- выбор нескольких видов отдыха в зависимости от длительности перерыва;
- оценка готовности к работе после перерыва и статистика эффективности отдыха;
- глубокий фокус с полноэкранным режимом и блокировкой сна экрана;
- встроенный перемещаемый lo-fi-плеер SoundCloud;
- настраиваемые звуковые и системные уведомления;
- светлая и тёмная темы;
- профиль, аватар, описание пользователя, достижения и уровни;
- leaderboard с возможностью отключить участие;
- панель администратора для просмотра статистики и управления пользователями.

## Структура проекта

```text
pomodoro-tracker/
├── frontend/              # React-приложение
│   └── src/
│       ├── api/           # запросы к REST API
│       ├── components/    # переиспользуемые компоненты
│       ├── context/       # авторизация, тема и lo-fi-плеер
│       ├── pages/         # страницы приложения
│       └── utils/         # вспомогательная логика
├── backend/               # Go-сервер
│   ├── cmd/server/        # точка входа
│   └── internal/
│       ├── handler/       # HTTP-обработчики
│       ├── middleware/    # JWT и проверка роли администратора
│       ├── model/         # структуры данных
│       ├── repository/    # запросы PostgreSQL
│       └── service/       # бизнес-логика
├── database/migrations/   # последовательные SQL-миграции
├── scripts/               # локальные сценарии запуска
├── Dockerfile             # production-сборка frontend и backend
└── render.yaml            # конфигурация Render
```

Backend построен по простой трёхслойной схеме:

```text
HTTP handler → service → repository → PostgreSQL
```

## Требования

- Go 1.26 или новее;

- npm;
- Docker — только если PostgreSQL запускается в контейнере.

## Локальный запуск

### 1. Клонирование и настройка

```bash
git clone https://github.com/stokm4n/pomodoro-tracker.git
cd pomodoro-tracker
cp .env.example .env
```

В `.env` необходимо указать `JWT_SECRET` длиной не менее 32 символов. Остальные
значения подходят для локальной разработки с PostgreSQL из `docker-compose.yml`.

### 2. PostgreSQL

```bash
docker compose up -d db
```

Проверка:

```bash
docker compose exec db pg_isready -U pomodoro -d pomodoro
```

### 3. Backend

```bash
cd backend
set -a
source ../.env
set +a
go run ./cmd/server
```

Backend будет доступен по адресу `http://localhost:8080`.

### 4. Frontend

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Frontend откроется по адресу `http://localhost:5173`. Vite автоматически
перенаправляет запросы `/api` на локальный Go-сервер.

### Быстрый запуск на настроенном Mac

В проекте также есть команда:

```bash
npm run dev
```

Сценарий `scripts/dev.sh` рассчитан на PostgreSQL 16 из Homebrew, работающий на
порту `5433`, и одновременно запускает backend и frontend.

## Миграции базы данных

SQL-файлы находятся в `database/migrations` и выполняются по имени файла.
Backend при запуске создаёт таблицу `schema_migrations` и применяет только те
миграции, которые ещё не выполнялись.

Новая миграция добавляется отдельным файлом:

```text
database/migrations/008_example.sql
```

Уже опубликованные миграции изменять не следует.

## Основные маршруты API

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/register` | регистрация |
| `POST /api/auth/login` | авторизация |
| `GET /api/profile` | профиль текущего пользователя |
| `GET /api/tasks` | список задач |
| `POST /api/tasks` | создание задачи |
| `POST /api/sessions/start` | запуск таймера |
| `GET /api/sessions/current` | текущая сессия |
| `GET /api/sessions/history` | история сессий |
| `POST /api/sessions/{id}/complete` | завершение интервала |
| `POST /api/sessions/{id}/readiness` | оценка готовности после перерыва |
| `GET /api/statistics` | статистика пользователя |
| `GET /api/leaderboard` | рейтинг пользователей |
| `GET /api/admin/users` | управление пользователями для администратора |

Защищённые маршруты принимают JWT в заголовке:

```text
Authorization: Bearer <token>
```

## Безопасность

- пароли хранятся только как bcrypt-хеши;
- JWT имеет ограниченный срок действия;
- пользователь имеет доступ только к собственным задачам и сессиям;
- административные маршруты дополнительно проверяют роль `admin`;
- SQL-запросы выполняются с параметрами через pgx;
- секреты и строка подключения не сохраняются в Git.

## Развёртывание

Production собирается многоэтапным `Dockerfile`:

1. Vite создаёт статическую сборку frontend;
2. Go компилирует исполняемый файл backend;
3. итоговый контейнер запускает Go-сервер, который обслуживает REST API и
   frontend.

Приложение развёрнуто в Render, PostgreSQL размещён в Neon, а домен подключён
через Cloudflare. Подробная инструкция находится в [DEPLOY.md](DEPLOY.md).

На бесплатном тарифе Render сервис может переходить в спящий режим. Поэтому
первое открытие после длительного простоя иногда занимает до одной минуты.
